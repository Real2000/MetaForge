**结论：无需任何调用方改动**——算法维度收敛在 crypto-util 单点，天然满足「双轨可配置」。

### 1.2 密文格式兼容设计

现状（SEC-10）：密文 4 段 `kid.iv.authTag.ciphertext`（16 进制；iv 16B/32hex、GCM tag 16B/32hex）；
解密格式探测按段数与 hex 长度路由，kid 命中密钥环。

双轨设计：**国密密文与 AES 密文段格式严格同构**（`kid.iv.mac.ct`，nonce 16B/32hex、
HMAC-SM3 截断 16B/32hex）——格式探测层零改动；**算法路由完全由 kid 命名空间承担**
（AES kid = sha256(主钥)前 8hex；国密 kid = SM3 派生域生成前 8hex——两域独立无碰撞）。

- 存量 AES 密文：kid 落 AES 密钥环 → 原路径解密，**字节级零回归**；
- 新国密密文：kid 落派生密钥集 → SM4 路径解密；
- 旧 3 段无 kid 密文：历史只可能 AES，回退逻辑零改动。

## 二、算法构造（关键决策）

### 2.2 构造方案：SM4-CTR + HMAC-SM3（Encrypt-then-MAC）

D-7 拍板口径为 SM4-GCM，但运行时无 SM4-GCM。原型采用密码学标准等价构造：

- **机密性**：SM4-CTR（CTR 模式 IND-CPA，随机 16B nonce）；
- **完整性/真实性**：HMAC-SM3(密钥域分离的 32B 认证钥) 对 `iv‖ct` 计算，**截断 128-bit**
  （与 GCM authTag 同位宽；HMAC 截断至 ≥128-bit 的安全界充分）；
- **组合安全**：Encrypt-then-MAC 为 IND-CPA + INT-CTXT 组合安全的标准范式（Katz-Lindell
  组合定理）——与 GCM 同等安全目标，仅构造形态不同；
- **校验次序**：先验 MAC（`crypto.timingSafeEqual` 恒时比较）再解密——fail-closed，密文
  篡改在完整性层被拒。

> 若密评/客户强制要求 SM4-GCM 硬件形态：二期路径为特定 OpenSSL 编译（enable SM4-GCM）或
> 密码卡/密码机接入（接口层仅替换 `sm4Keyset`/加解密两函数，双轨框架不变）。

### 2.3 密钥派生（零新供给面）

单主密钥（SEC-10 三级来源不变）经 **SM3 域分离派生**国密密钥集：

```
sm4Key(16B) = SM3(0x01 ‖ 主钥)[0..16)     // SM4 加密钥
macKey(32B) = SM3(0x02 ‖ 主钥)             // HMAC-SM3 认证钥
sm4Kid      = SM3(0x03 ‖ sm4Key)[0..8)     // kid（绑定加密钥）
```

- **零新增配置面**：国密模式无需单独供给密钥（主钥不变）；
- **轮换正交**：密钥环内每把主钥（env 主/PREV/db 旧）均可派生对应国密密钥集——换钥后
  旧国密密文照解；
- 二期（正式密评部署）：可替换为专用国密密钥供给（独立 env/密码机），仅派生函数与 kid
  随之变化，存量密文按密钥环解密不受影响。

## 三、切换开关

`AGENT_CRYPTO_ALGO` 环境变量（缺省 `aes-gcm`）：

| 值 | 行为 |
|---|---|
| `aes-gcm`（缺省） | 与历史行为字节级一致（默认不动，生产零影响） |
| `sm4` | 新写入密文走国密（SM4-CTR+HMAC-SM3，sm4Kid 标记）；存量 AES 密文继续可解（双轨并存） |

`keyInfo()` 新增 `algo`（当前写入算法）与 `sm4Kid`（国密 kid）字段——供巡检/切换审计；
`versions` 维持纯 AES kid 集（启动日志零变化）。
