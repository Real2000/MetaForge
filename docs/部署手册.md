# 智能体开发平台 · 部署手册

> 适用版本：V3.2 · 更新日期：2026-11-10
> 三种部署路径：macOS 双击（最简） / Docker（服务器推荐） / systemd（Linux 常驻）

## 0. 部署前须知

| 项 | 要求 |
|---|---|
| Node.js | ≥ 18（Docker/systemd 路径由对应机制提供，macOS 双击需自行安装） |
| 端口 | 3210（默认，可通过 `PORT` 环境变量修改） |
| 磁盘 | ≥ 1GB（含向量库与用户上传产物，按用量增长） |
| 首次启动 | 自动建库并种子全套演示数据（4 个账号 / 10 个智能体 / 2 个知识库 / 会话历史） |
| 首次登录 | `admin / admin123`，**强制改密**（安全机制，改一次后长期有效） |

**数据目录结构**（默认 `<项目根>/data/`，可用 `AGENT_DATA_DIR` 重定向）：

```
data/
├── platform.db      # 生产库（SQLite，含全部业务数据）
├── secrets.json     # 加密密钥（ENCRYPTION_KEY / jwt_secret）——备份必带，丢失=已加密的模型 Key 全部作废
└── vector-store/    # 向量库（LanceDB）
```

1. 双击项目根目录 **`启动平台.command`**

## 2. 路径二：Docker（服务器推荐，一条命令全栈）

### 2.1 一键启动

```bash
docker compose up -d                      # 构建并启动平台（推荐起步，不拉 OCR 大镜像）
docker compose --profile ocr up -d       # 平台 + PaddleOCR（扫描件识别增强，首次拉取 ~2GB）
```

- 平台镜像：多阶段构建（`node:18-slim`），原生模块（better-sqlite3 / vectordb）在 builder 阶段编译
- 数据持久化：三个 named volume（`platform-data` / `platform-uploads` / `platform-downloads`）
- 健康检查：内置 `curl /api/health`（30s 间隔）
- OCR 可选：默认不启动（`profile=ocr` 隔离）；启用后需取消 `docker-compose.yml` 中 `PADDLEOCR_URL` 注释并 `docker compose up -d` 重建容器
- **中文目录名注意**：项目目录含非 ASCII 字符时 Compose 自动生成的项目名为空会报错 `project name must not be empty`，命令前加 `-p agent-platform`（或导出 `COMPOSE_PROJECT_NAME=agent-platform`）

### 2.2 自定义端口与环境

复制 `.env.example` 为 `.env` 按需修改，常用项：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 3210 | HTTP 监听端口 |
| `AGENT_DATA_DIR` | ./data | 数据目录（容器内默认 /app/data，勿改） |
| `AGENT_JWT_SECRET` | 自动生成 | JWT 签名密钥（≥16 字符，`openssl rand -hex 32` 生成）；不设时自动生成落盘 data/secrets.json，中途更换会使全部登录会话失效 |
| `AGENT_PWD_SALT` | 内置 SALT | 全局密码加盐盐值（≥8 字符）；**存量部署保持默认**，中途更换会使全部用户密码失效 |
| `AGENT_TOKEN_TTL_HOURS` | 168 | 登录 Token 有效期（小时，168 = 7 天） |
| `PADDLEOCR_URL` | （空） | OCR 服务地址；启用 `--profile ocr` 后填 `http://paddleocr:9300` |
| `TZ` | Asia/Shanghai | 时区（影响日志/定时任务） |

### 2.3 OCR 服务说明

- PaddleOCR 用于扫描版 PDF 的文字识别增强（`docker-compose.yml` 已编排，`profile=ocr` 隔离默认不启动）
- **不启动 OCR 不影响平台核心功能**：扫描件解析文本过短时静默降级
- 启用：`docker compose --profile ocr up -d`，并取消 compose 中 `PADDLEOCR_URL` 注释后 `docker compose up -d platform` 重建
- 单独启动：`docker compose -f docker-compose.paddleocr.yml up -d`（端口 9300，详见 `docs/PaddleOCR部署说明.md`）

### 2.4 数据备份（Docker 路径）

```bash
docker cp agent-platform:/app/data ./backup-$(date +%Y%m%d)   # 含 platform.db + secrets.json
docker exec agent-platform sqlite3 /app/data/platform.db "PRAGMA integrity_check;"  # 校验
```

## 3. 路径三：systemd（Linux 服务器常驻）

### 3.1 安装步骤

```bash
# 1) 部署代码到 /opt/agent-platform（git clone 或解压）
sudo mkdir -p /opt/agent-platform && sudo chown $USER /opt/agent-platform
# （把项目代码放入该目录）

# 2) 安装依赖（服务器需 Node ≥ 18 与编译工具链）
cd /opt/agent-platform && npm install --no-audit --no-fund

# 3) 创建运行用户与配置
sudo useradd -r -s /usr/sbin/nologin agent 2>/dev/null || true
sudo mkdir -p /etc/agent-platform
sudo cp .env.example /etc/agent-platform/.env     # 按需编辑（至少确认 PORT/AGENT_DATA_DIR）

# 4) 安装 systemd 单元（仓库已带：scripts/agent-platform.service）
sudo cp scripts/agent-platform.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now agent-platform

# 5) 验证
systemctl status agent-platform
curl http://localhost:3210/api/health
```

### 3.2 运维命令

```bash
sudo systemctl restart agent-platform    # 重启（优雅停机：处理完存量请求并落库）
journalctl -u agent-platform -f          # 实时日志
sudo systemctl disable --now agent-platform   # 停止并取消自启
```

> 单元文件要点：`Restart=on-failure`（崩溃自愈）、`KillSignal=SIGTERM`（触发平台内置优雅停机）、`PrivateTmp/NoNewPrivileges`（安全加固）。运行目录为 `/opt/agent-platform`，如部署在其他路径需同步修改单元文件中的 `WorkingDirectory`/`ExecStart`。
