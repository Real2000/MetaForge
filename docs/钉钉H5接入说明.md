# 钉钉 H5 微应用接入说明（V3.1 #11 · 2026-11-03）

> 当前状态：**方案设计 + mock 实现已完成**（无企业凭证下的可运行演示链路）。
> 真实联调需在钉钉开放平台创建应用并配置凭证后进行（见第四节）。

## 一、能力总览

| 端点 | 方法 | 鉴权 | 用途 |
|---|---|---|---|
| `/api/dingtalk/h5/config` | GET | 无 | 模式发现：`{ enabled, mock, corp_id, agent_id }`，前端据此渲染免登入口 |
| `/api/dingtalk/h5/login` | POST | 无（免登入口） | **免登换 JWT**：真实模式 `auth_code` 换 userid；mock 模式 `mock_user` 直登本地账号 |
| `/api/dingtalk/h5/jsapi-config` | POST | 无（登录前需初始化 dd.config） | `dd.config` 所需签名：`{ agentId, corpId, timeStamp, nonceStr, signature }` |
| `/api/dingtalk/h5/send-msg` | POST | **Bearer JWT** | 工作通知：`{ userid_list, title, content }`（单次至多 20 人） |

限流：login/jsapi-config/send-msg 共享 `dingtalk-h5` 滑动窗口（10 次/分钟/IP）。

## 二、免登流程（真实模式）

```
钉钉工作台打开 H5 微应用
  → 前端 GET /api/dingtalk/h5/config（拿 corp_id/agent_id，enabled=true）
  → 前端 POST /h5/jsapi-config { url: 当前页URL } → 拿签名
  → 前端 dd.config({ agentId, corpId, timeStamp, nonceStr, signature, jsApiList: [...] })
  → 前端 dd.runtime.permission.requestAuthCode({ corpId }) → auth_code
  → 前端 POST /h5/login { auth_code }
      服务端：gettoken(appkey/secret) → access_token（7000s 内存缓存）
            → POST /topapi/v2/user/getuserinfo { code } → userid
            → upsertDingtalkUser（与回调/扫码登录同一套映射：手机号命中 → dingtalk_{userid} 新建）
            → sign JWT（与密码登录同构：同 SECRET/TTL/jti/黑名单）
  → 响应 JSON body 返回 { token, user, must_change_pwd }（#14 安全约定：token 不走 URL）
  → 前端 setLogin 进平台
```

### 安全设计要点（对齐安全报告 T1.1-T1.4）

1. **JWT 全程 JSON body 交付**——不走 302 URL / hash 参数（复用 #14 一次性交换码评审结论）
2. **mock 通道自动关闭**：`h5Configured() = APP_KEY/SECRET 齐备` 时 `mock_user` 分支不可达——生产环境不可能被 mock 登录绕过（冒烟已断言）
3. **auth_code 一次性**：钉钉侧 code 短时效且单次有效，服务端无缓存重放面
4. **JSAPI 签名按调用页 URL 计算**（钉钉官方算法 `HMAC-SHA256(jsapi_ticket, nonceStr+timeStamp+url)`）
5. **redirect_uri 固化**：扫码登录沿用 auth.js 的 origin 绑定校验（H1 止血），H5 免登无 redirect 环节，不引入新面

## 三、mock 模式（当前默认）

凭证未配置（secrets 表无 DINGTALK_APP_KEY/SECRET）时：

- `GET /h5/config` → `{ enabled: false, mock: true }`
- 登录页自动显示「📱 钉钉免登（演示）」按钮 → `POST /h5/login { mock_user: 'demo' }` → 直登 demo 账号（演示 JWT 真签发，链路与真实模式同构）
- `jsapi-config` 用确定性本地票据（`sha256(appkey:h5)` 派生）跑同一套 HMAC 签名算法——前端 dd.config 前置链路可完整调试
- `send-msg` 走 op_logs 审计留痕并返回成功（`data.mock: true`）

## 四、真实联调步骤（获得企业凭证后）

1. **钉钉开放平台**（open-dev.dingtalk.com）→ 应用开发 → 创建 **H5 微应用**：
   - 记录 `AppKey` / `AppSecret` / `AgentId`；企业corpId 在「企业信息」页
   - 应用首页地址：`https://你的平台域名/#/home`（或 `#/login`）
   - **服务器出口 IP 白名单**：把平台服务器公网 IP 加入（否则 gettoken 报 60020）
2. **平台侧配置**（管理后台「密钥管理」或 secrets 表）：
   ```
   DINGTALK_APP_KEY    = AppKey
   DINGTALK_APP_SECRET = AppSecret
   DINGTALK_AGENT_ID   = AgentId（工作通知发送方）
   DINGTALK_CORP_ID    = 企业 corpId（回显给前端 dd.config）
   ```
   > 配置完成后 mock 通道自动关闭（无需改代码），登录页演示按钮自动隐藏。
3. **前端 SDK 接线**（真实联调阶段的前端工作，mock 阶段已预留挂载点 login.js `#dtH5Btn`）：
   - 引入官方 `https://g.alicdn.com/dingding/dingtalk-jsapi/3.0.25/dingtalk.open.js`
   - `dd.config`（jsapi-config 签名）→ `dd.ready` → `dd.runtime.permission.requestAuthCode` → POST `/h5/login`
4. **JSAPI 权限申请**：选人（`biz.contact.pick`）/拍照/定位等能力在开放平台「JSAPI 权限」中逐项申请
5. **联调验证清单**：
   - [ ] 工作台打开应用 → 免登直接进首页（无登录页跳转）
   - [ ] `gettoken` 出口 IP 白名单生效（无 60020）
   - [ ] auth_code 换取的用户与组织同步回调建的用户是同一账号（unionid/userid 一致性）
   - [ ] 工作通知送达（send-msg → task_id → 钉钉客户端收到）
   - [ ] token 过期后免登重试（重新 requestAuthCode）

## 五、已固化的契约（冒烟测试覆盖）
